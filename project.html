Project 01 Cybersecurity internship

USB Security Rollout

2025 Systemtech Services Ltd Endpoint security

Deploying ManageEngine Device Control Plus so a company could decide exactly which USB devices touch its computers, and for how long.

Overview

During my internship in the cybersecurity unit at Systemtech Services Limited, I worked on deploying Device Control Plus. It's a tool that controls and monitors USB drives and other peripherals on company computers, so sensitive data can't walk out the door on a flash drive.

I installed the agent on each work machine, wrote the access policies, grouped the computers, and rolled the policies out to them.

The problem

Unmanaged USB drives are one of the easiest ways for data to leave a company, and for malware to get in. Blocking every device isn't realistic because people still need to move files.

The company needed a way to trust specific devices, block everything else, and still give someone short-term access when they had a real reason.

Features

  1. Agent installation

    Installed the lightweight Device Control Plus agent on every target work computer so policies could be enforced on each one.

  2. Trusted device list

    Added approved flash drives and hard drives as trusted devices using their parent and device instance paths.

  3. One-way file transfer

    A policy that lets files come in from a USB drive but blocks copying company files out to one.

  4. Temporary access

    Grants a user USB access for a set time (fixed or windowed, for example 30 minutes or an hour) and then revokes it automatically.

  5. Group-based deployment

    Created computer groups and attached policies to them, so each rule reached exactly the machines it was meant for.

What I learned

A policy does nothing on its own. It only reaches machines once it's attached to a computer group, so planning the groups mattered as much as writing the rules.

The bigger lesson was how classroom theory turns into real settings. The peripheral security ideas from my Computer Security course made sense on paper, but choosing between blocking, read-only and temporary access for real people taught me to think about how users actually work, not just what's most secure.

I also learned to ask for help early. Working alongside the server engineers and my supervisor saved me hours of guessing.
